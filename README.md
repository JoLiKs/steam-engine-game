# Последний котёл

Паропанк-игра в браузере про кочегара старого парового котла **Агафьи** — единственного источника тепла в городе Ферроград. Десять зимних ночей, четыре вентиля и вопрос, на который нет правильного ответа: *кому достанется пар?*

**Играть:** https://steam-engine-game.pages.dev

## Концепт

Один тугой цикл: держите давление в зелёной зоне, подбрасывайте уголь и **делите пар между четырьмя районами**. Каждый район — это человеческая цена:

| Вентиль | Что даёт | Чем платите |
|---|---|---|
| **Госпиталь** | Больные выживают | Самый быстрый расход пара |
| **Кварталы** | Люди не замерзают | Нужно много пара в метель |
| **Завод** | Уголь для топки | **Усталость рабочих** — если шкала дойдёт до 100%, смена падает и завод встаёт |
| **Фильтры** | Чистят дым | Едят пар; без них город задыхается, а в воздухе копоть |

Смысл — не в очках, а в **цене тепла**. Между ночами вам встречаются четыре решения (подручный Тимка, двойная смена, бурый уголь, слобода), и в каждом есть «выгодный» ответ, который платит чужим здоровьем: детским трудом, усталостью смены, копотью в лёгких. Они накапливаются в скрытых счётчиках (*цена смены*, *средний дым*, *население*) и определяют одну из **шести концовок**:

* **Свет в каждом окне** — город выжил и не заплатил чужой усталостью и чужим воздухом;
* **Дым над городом** — выжили, но надышались копотью;
* **Железные люди** — выжили на плечах загнанной смены;
* **Холодный расчёт** — котёл цел, но слишком многих потеряли;
* **Взрыв Агафьи** — давление в красной зоне больше 2,5 секунд;
* **Тишина** — меньше половины жителей дожили до обоза.

Игра честная: любую «жёсткую» цену можно обойти мастерством (быстрые руки, вовремя сбросить вентиль завода, не жалеть фильтры), но тогда не хватит угля или рук. Так выбор превращается в механику, а не в текст.

## Управление

| Действие | Клавиатура | Мышь / касание |
|---|---|---|
| Подбросить уголь | **Пробел** | кнопка «Уголь» |
| Выбрать вентиль | **1–4**, **←/→** (или A/D) | нажать на колонку |
| Открыть/закрыть вентиль | **↑/↓** (или W/S), **Shift** — крупнее | тянуть штурвал, колесо мыши |
| Заделать утечку | **F** / **Enter** | нажать на красный «!» |
| Пауза | **P** / **Esc** | кнопка в углу |
| Звук вкл/выкл | **M** | Настройки |

В меню паузы: переиграть ночь, настройки, «как играть». Прогресс автоматически сохраняется в `localStorage` в начале каждой ночи и на экранах выбора; кнопка «Продолжить» на титуле возобновляет игру. Настройки: «Звук включён» (общий выключатель), **«Звуки»** и **«Музыка»** (независимые ползунки), «меньше движения», тряска экрана, **«Отправлять анонимную статистику»**. Системная настройка `prefers-reduced-motion` включает «меньше движения» автоматически (меньше частиц, без тряски и мерцания). Мигающих эффектов нет.

## Как это сделано

* **Без сборки, без зависимостей.** Ванильный JS (ES-модули), Canvas 2D, ни одного внешнего запроса. Шрифты — системные.
* **Вся графика — код**: латунь/медь/железо — градиенты и клёпки; шестерни — предрисованные спрайты, вращаются от расхода пара; манометр, труба с бегущими каплями пара, пламя, угольный бункер, город с окнами, которые гаснут по мере потерь.
* **Звук синтезируется** в WebAudio: шипение пара (фильтрованный шум), гул котла, лопата, клапаны, шестерёнки, финальные аккорды и **музыкальная петля** (минор, шарманочное арпеджио, поршневой ритм, темп растёт с давлением).
* **Архитектура.** `src/sim.js` — чистая детерминированная симуляция (фиксированный шаг 1/60 с, ГСЧ mulberry32 с состоянием в сохранении); `src/data.js` — ночи, события, реплики, карточки, концовки; `src/render.js`/`draw.js`/`fx.js`/`layout.js` — отрисовка, частицы, раскладка (две: книжная для телефона и альбомная); `src/main.js` — цикл с накоплением времени, ввод, UI, сохранения; `src/bot.js` — бот для тестов и балансировки.
* **HiDPI**: размер холста = CSS-размер × devicePixelRatio (до 2.5, на телефонах до 2), статичный фон кэшируется в offscreen-canvas.

### Рейтинг и очки

```
счёт = ночи × 100 + жители ÷ 2 + бонус концовки − падения смены × 25 − средний дым (%)
бонус: Свет +300 · Дым +150 · Железо +150 · Холод +50 · Взрыв/Тишина 0
```

* **По очкам** — лучший счёт игрока; **по выживанию** — больше ночей пройдено → больше жителей → больше очков. В таблице один результат на игрока (анонимный случайный id в `localStorage`, на сервере хранится только HMAC).
* Взрыв или «Тишина» на 7-й ночи дают честные, но малые очки: рейтинг награждает и мастерство (жители, дым, усталость смены), и дойденность.
* Результат отправляется **только по кнопке** на финальном экране. Если сервер недоступен, кнопка «Рейтинг» и форма просто не показываются — игра работает как раньше (проверено тестом с заблокированным `/api/g/*`).

### Защита от мусора и накрутки (бэкенд)

* **Билет прохождения**: при старте игры сервер выдаёт подписанный HMAC-билет (id + время выдачи, ничего не хранится). Результат принимается только с билетом, один билет — один результат.
* **Серверная проверка правдоподобия**: счёт пересчитывается из показателей и должен совпасть; диапазоны (ночи 0–10, жители 0–1000, дым 0–100, падения 0–60…); согласованность концовки (например, «Свет/Дым/Железо» — только после 10 ночей и при ≥ 740 жителей, «Холод» — при < 740, «Свет» — не более 2 падений смены; «Взрыв»/«Тишина» — только до 10-й ночи, «Тишина» — не более 500 жителей); **время**: нельзя пройти быстрее 50 % суммарной длительности пройденных ночей по *серверным* часам от выдачи билета.
* **Лимиты**: на реальный IP (его сообщает Cloudflare Worker) — билеты 12/мин, события 90/мин, результаты 4/мин и 25/сутки, чтение 120/мин; 80 событий на сессию; тело запроса ≤ 4 КБ; вход в админку — 5 неудач → блок на 15 минут.
* **Ник**: нормализация NFKC, остаются только буквы/цифры/пробел/дефис, ≤ 16 символов (всё остальное, включая `<>&"'/:`, вырезается), строки со ссылками/`@` → «Аноним»; пусто или < 2 символов → «Аноним». Словаря ругани нет. В интерфейсе выводится через `textContent` (никакого `innerHTML` с чужими данными).
* **Приватность**: IP не хранится (только суточный HMAC, на следующий день хеш другой), cookie у игры нет, id игрока хешируется, user-agent обрезается до 40 безопасных символов.

> Честно: клиентский код открыт, поэтому абсолютной защиты от накрутки нет — можно подделать запрос, который пройдёт все проверки правдоподобия (например, выдуманное «хорошее» прохождение, потратив реальные 5+ минут на билет). Проверки отсекают тривиальные подделки и массовый спам; админка позволяет скрыть/удалить запись.

### Админка

* Адрес: **https://steam-engine-game.pages.dev/admin** (только на этом хосте; на превью-деплоях `*.pages.dev` — 404). Логин — статическая страница на Pages; `_worker.js` проксирует `/api/admin/*` и `/admin/panel*` на бэкенд с общим секретом. Панель (HTML/JS/CSS) отдаёт **только бэкенд и только по валидной сессии** (cookie `__Host-seg_admin`, HttpOnly, Secure, SameSite=Strict + CSRF-токен + проверка Origin); без сессии — 401.
* Вкладки: **Обзор** (сессий, завершено, средняя длительность, распределение концовок, «дошли до ночи N», платформы, размеры экрана, сессии по дням, средние положения вентилей), **Сессии** (фильтры: платформа, концовка, статус, ночи, длительность, даты; сортировка; подробности/события; удаление; CSV), **Рейтинг** (поиск, скрыть/показать, удалить, CSV), **Обслуживание** (очистка старых данных; автоматически — старше 180 дней).
* CSV защищён от формул Excel (`=`, `+`, `-`, `@` в начале ячейки экранируются).

### Архитектура онлайн-части

```
браузер ──(тот же origin)──► Cloudflare Pages: статика + _worker.js ──(X-SEG-Proxy-Secret, X-SEG-Client-IP)──► nginx /steam/ ──► uvicorn 127.0.0.1:8932 (systemd: steam-engine-game) ──► SQLite
```

* Бэкенд (`backend/`): FastAPI + SQLite (WAL), без внешних зависимостей, кроме fastapi/uvicorn. Прямые запросы без секрета прокси → 403 (кроме `/api/health`). CORS — только `https://steam-engine-game.pages.dev`.
* Публичное API: `POST /api/g/run` (билет), `POST /api/g/event`, `POST /api/g/score`, `GET /api/g/leaderboard?board=score|survival`.
* Секреты (пароль админки — scrypt-хеш, ключ подписи, секрет прокси) лежат только в `/etc/steam-engine-game.env` на сервере и в секретах проекта Pages. В репозитории их нет.

### Мобильная версия

* `viewport-fit=cover`, `user-scalable=no`; `touch-action: manipulation` на странице и `none` на холсте — двойной тап не зумит; отступы **safe-area** заданы на самом холсте (вырез/жестовая панель не закрывают HUD).
* Две раскладки: книжная (телефон) и альбомная; поворот на лету без потери игры. Цели касания ≥ 44 CSS-px (колонки вентилей, «Уголь», утечки, пауза — зона нажатия расширяется на мелком масштабе); кнопки меню ≥ 48 px; ползунки ≥ 44 px.
* Аудио создаётся/возобновляется по первому касанию (`pointerdown`/`touchend`); плотность пикселей на телефонах ограничена 2×.
* Проверено эмуляцией в headless Chrome (Playwright): 390×844, 360×640, 412×915 и ландшафт 844×390 — скриншоты в `screenshots/v1.1/`. **Реальные устройства не проверялись** (см. ограничения в CHANGELOG).

## Тесты и баланс

```bash
npm install                                  # playwright-core, puppeteer-core (используется системный Chrome)
bash tests/run-all.sh                        # всё сразу (≈ 8 минут)
node --test tests/                           # юниты: логика (20), звук (5, мок AudioContext), счёт (общие векторы с бэкендом)
node tests/audio_offline.js                  # звук: реальный OfflineAudioContext — каналы «Звуки»/«Музыка» независимы
(cd backend && python -m pytest -q)          # бэкенд: 43 теста (валидация, лимиты, ник, билеты, CORS, 401, CSRF, админка, CSV)
node tests/pw/rating_admin.pw.js             # Playwright: рейтинг, телеметрия, офлайн, админка (стенд: бэкенд + настоящий _worker.js)
node tests/pw/mobile_visual.pw.js            # Playwright: 4 мобильных и 3 десктопных вьюпорта, касания, манометр, дым, safe-area, FPS
node tests/e2e.js                            # Puppeteer: игра с нуля до концовки на 1280×800 и 390×844
node scripts/balance.mjs                     # таблица: бот × политика решений × 20 seed → концовки
```

`tests/devstack.js` поднимает локальный стенд, повторяющий прод (Python-бэкенд во временной папке + статика + `_worker.js`). Нужен Python 3.10+ с `fastapi uvicorn pytest httpx` (путь — `SEG_PY`).

Баланс подбирался симуляцией: аккуратный бот выигрывает 20 из 20 (концовка «Свет»), небрежный «жадный» — получает «Дым»/«Железо», бот, который не касается вентилей, или перегревает котёл, — проигрывает («Тишина»/«Взрыв»), «скупой» бот (держит вентили на 55% от нужного) — «Холодный расчёт». Все шесть концовок достижимы ботом.

Отладочный режим: `?debug` открывает `window.__game` (используется только тестами).

## Деплой

* **Игра/Pages**: `scripts/deploy.sh` (wrangler 3, проект `steam-engine-game`; публикуются только файлы сайта). Секрет прокси задаётся в проекте Pages как `SEG_PROXY_SECRET`.
* **Бэкенд**: `backend/deploy/` — unit systemd (`steam-engine-game.service`, порт 8932, пользователь без shell, `ProtectSystem=strict`) и фрагмент nginx (`location /steam/`). Переменные окружения (`SEG_*`) — в `/etc/steam-engine-game.env` (chmod 640 root:seg): `SEG_SECRET_KEY`, `SEG_PROXY_SECRET`, `SEG_ADMIN_PASSWORD_HASH` (получить: `echo -n 'пароль' | python -m app.hashpw`), `SEG_ALLOWED_ORIGINS`, `SEG_ADMIN_ORIGINS`.
